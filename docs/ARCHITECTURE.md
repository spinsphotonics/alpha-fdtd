# Architecture

alpha-fdtd is a C library (`libalphafdtd.so`, API in `include/alpha_fdtd.h`) and a thin ctypes wrapper
(`python/alpha_fdtd`). Everything that runs at plan or run time is in the C library; the Python package only marshals
NumPy arrays and turns status codes into exceptions.

## Source layout

| file | what it does |
|---|---|
| `src/api.cpp` | the C entry points: argument checks, status codes and the thread-local error text, the per-plan lock, the exception firewall (no C++ exception crosses the ABI), wisdom text |
| `src/plan.cpp` | device checks, the memory-mode decision, schedule choice (ESTIMATE by rules and a cost model, MEASURE / PATIENT by timing candidates on the plan's GPUs), the per-process self-check, `afdtd_execute` |
| `src/boxio.cpp` | caller boxes to and from the state: strides, BF16 / F32 conversion, the lower-wall rule; the host-memory domain (allocation, pinning) |
| `src/object.cu` | everything that touches one generated kernel text, compiled once per (kernel text, architecture): the in-GPU-memory executor (1 to 8 GPUs over one virtual-memory window), the host-memory executor, the step-tail kernels, box and checksum kernels |
| `src/kernels/*.cuh` | the kernel texts, generated by `tools/gen` and committed |
| `src/internal.hpp` | the state layout and the interface between the host code and the kernel objects |

## Kernels

| kernel text | what | compiled for |
|---|---|---|
| `zs7_tma` | z-streamed register pillars, 7 steps per trip, 24 owned y cells per pillar, TMA bulk copies fed by a producer warpgroup | sm_90a (H100, H200), sm_100a (B200), sm_103a (B300) |
| `zs7_cpasync_l2h3` | the same IR lowered to cp.async with mbarriers, copies on the compute warps, L2 hint policy 3 | sm_80 (A100) |
| `zs7_cpasync_l2h0` | as above, L2 hints off | sm_80 (A100) |

All objects link into one library: SASS for four architectures and no PTX, so an unsupported GPU is refused at plan
time instead of running a JIT-compiled kernel. The schedule parameters (persistent grid size, strip width, start gate,
pool size; in host memory the ring slots and depth) are runtime arguments of the executors, so the kernel set stays at
three texts.

## Planning

1. `afdtd_plan_create` checks the arguments and devices and picks the memory mode: GPU memory if the state fits the
   free memory of every GPU less a small reserve (256 MiB plus the box staging buffer), with smaller block pools if
   only those fit; otherwise host memory if it fits `host_bytes`; otherwise `AFDTD_ENOMEM` with both byte counts.
2. A wisdom record for the problem (kernel-set id, GPU model, GPU count, size, memory mode) of sufficient rigor is used
   if it passes the same legality checks as a planned schedule.
3. Otherwise ESTIMATE takes the rule-based pick; MEASURE and PATIENT time each candidate on the plan's own state for
   about one second per timing, in alternating order, and keep the fastest.
4. Every (kernel object, device) passes a self-check once per process: a small random lossy problem through the
   executor, compared value by value with the step-tail kernels, which compute the reference formula one step at a time.

## Host memory

The domain lives in pinned host memory as rows of 24 y cells. A ring of rows is resident on the GPUs; each `execute`
call streams every row in once per round, advances it up to `qmax` passes of 7 steps, and writes it back. Launches
alternate between two streams per GPU so that launch L + 1 fills the SMs that launch L releases; launch L + 1 starts
only once launch L has a resident block (stream wait on its block counter), which keeps the persistent kernels free of
deadlock. A watchdog turns a launch that does not finish within 120 s into `AFDTD_EDEVICE` instead of a hang.

## Wisdom format

```
alpha-fdtd-wisdom 1
kset=<12 hex> gpu="<device name>" cc=9.0 sm=132 ngpus=1 size=1338x1344x1336 mode=gpu rigor=measure rate=3.17e11 sched="obj=zs7_tma grid=132 tx=12 gate=1 mx=1100"
```

`kset` is a hash of the kernel texts and executor sources: a build that changes them ignores old records (they are
kept on export, never used). The schedule text is opaque to users.

## Design notes

- **One plan, one state.** A plan owns the state instead of transforming caller buffers. The state of a large domain
  is terabytes in BF16 with a padded layout that only the executors understand, so copies in and out are explicit
  (`afdtd_set`, `afdtd_get`) and cost what they move.
- **The C library owns run time.** Planning, timing, wisdom, box I/O, offload and errors are all in C/C++. The Python
  package makes exactly one C call per method (`Plan.set` adds one `afdtd_plan_info` call for the wall warning) and
  does no numerics. Any language with a C FFI gets the same library.
- **Few kernel texts, runtime knobs.** Grid size, strip width, start gate and pool size, and in host memory the ring
  slots and depth, are executor arguments, not template parameters. Only the copy mechanism (TMA or cp.async) and the
  L2 hint policy need separate texts. The fat binary holds three texts as five objects over four architectures, and
  builds in about 15 s on 16 CPUs.
- **SASS only, no PTX.** Every supported architecture gets ahead-of-time SASS; an unsupported GPU is refused at plan
  time rather than running a JIT-compiled kernel that was never verified.
- **Seven steps per trip.** The fast path advances 7 steps per pass over the domain. Step counts that are not a
  multiple of 7 finish on separate one-step tail kernels. These compute the reference formula directly, so any step
  count and any split into calls give the same bits.
- **The lower wall is enforced, not trusted.** The engine's reads at index 0 assume the wall values are +0. `afdtd_set`
  writes +0 there and counts what it replaced, because a nonzero value would make the engine and the reference
  formula disagree silently.
- **The absorbed H form.** Dropping the H coefficient saves one multiply and one array per H component. It is
  bit-identical to the textbook form when `C_H` is a power of two. The price is a units convention the caller must
  follow, which is why it is restated in the header, the README and every Python docstring that takes Cb or H.
- **Synchronous calls, little global state.** Every call finishes its GPU work before it returns; host threads that a
  call starts (parallel first touch and copies of host-memory domains) are joined before it returns. Each plan has its
  own lock. The only library-wide state is the wisdom table and the per-process self-check cache.
