# tools/gen: kernel generator (developer tool)

`src/kernels/*.cuh` are generated by this directory and committed; building the library never runs Python.

```
python3 tools/gen/gen.py            # regenerate src/kernels/
python3 tools/gen/gen.py --check    # exit 1 unless the committed texts equal the generated ones, byte for byte
```

| kernel text | what | built for |
|---|---|---|
| `zs7_tma` | z-streamed register pillars, 7 steps per trip, 24 owned y-cells per pillar, TMA bulk feed, L2 hint policy 3 | sm_90a, sm_100a, sm_103a |
| `zs7_cpasync_l2h3` | the same IR lowered to cp.async with mbarriers, copy work on the compute warps, L2 hint policy 3 | sm_80 |
| `zs7_cpasync_l2h0` | as above, L2 hints off | sm_80 |

Pipeline: `gen3.py` (IR of one pillar trip) -> `smx.py` (IR load hoisting) -> `cudagen6.py` (CUDA text) -> `persist.py`
(persistent kernel, publish interval, L2 hints) -> for sm_80, `sm80.py` (cp.async lowering, folding the copy roles onto the
compute warps). Every transform is a text rewrite asserted to apply exactly; the arithmetic is unchanged by all of them.
Only the code paths that the configurations in `gen.py` reach are kept.

The committed texts differ from the texts whose speed and exactness were first measured only in comments (the code
lines, comments removed, are identical); speed and bit-identity of the shipped build are checked by the GPU tests and
`docs/PERFORMANCE.md`.
